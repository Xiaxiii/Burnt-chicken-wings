# 焦香鸡翅· Burnt chicken wings 🍗

SillyTavern（酒馆）聊天补全预设工具：整理分组、跨预设缝合、思维链检查、方案、加载体检、预设清理。

缝合时先分析两个预设让条目生效的方式，再自动调整写法，使缝入的条目在目标预设中正常生效。可识别的写法包括：

- 变量写法：正文写入变量（setvar / addvar）、各条目登记问句变量、向汇总变量追加内容
- 思维链读取条目的方式：读取变量，或在文字中提及条目名称
- 初始化条目、外层标签（如 `<text_style>`）、深度插入、`{{if}}` 条件、EJS 脚本、正则

缝合预览逐条列出：条目在原预设中的作用、缝入后的调整、思维链能否读取。需要时可一键接入思维链。

### 扩展版（推荐）

```
https://github.com/Xiaxiii/Burnt-chicken-wings
```

更新：在扩展管理中点「更新」，或在扩展页「焦香鸡翅」设置框中点「检查更新」。设置框标题旁显示当前版本号。

### 脚本版（酒馆助手）

待功能稳定后发布。两个版本同时安装时，只有扩展版会启动。

## 打开方式

- 魔棒菜单 →「焦香鸡翅」（名称可在扩展页设置框中点「修改」更改）
- 扩展页「焦香鸡翅」设置框 →「打开」
- 在输入框发送 `/atelier` 或 `/焦香鸡翅`
- 悬浮球（默认关闭）：在扩展页设置框勾选「显示悬浮球」，或在「更多 → 外观」最上面打开开关。点一下打开，按住拖动，松手贴到左右边

修改即时自动保存，有修改时可「撤销」，或点「完成」结束这一批修改。保存前会核对预设有没有在别处被改过，改过就先问你。每批修改开始前自动备份一次，每个预设保留最近 10 份，可在顶栏的时钟按钮中查看、恢复或下载。备份只存在当前浏览器里，换设备或清除浏览器数据后就没有了。

普通保存只刷新柏宝箱当前预设的分组缓存，不会广播预设导入事件，避免误触发其他扩展的「导入自动迁移」。真正导入预设仍由酒馆原有流程处理。

## 基本操作

- **选位置**（缝合的目标、整理页的移动）：点组名，放在该组之后；展开分组后点组内条目，放入组内。
- **新建分组**：点「＋ 新建分组」，填写名称，再点一个位置。新分组为空，之后可移入或缝入条目。
- **归整分区**：出现「第 1/4 段」等提示时，说明同组成员被其他条目隔开。点列表提示中的「归整分区」，或「工具 → 智能分组 → 归整分散的分区」，勾选后预览完整顺序，再一次收拢到各组首段。保留组内先后、正文和开关，可撤销。此操作会调整预设条目顺序。
- **识别未分组条目**：「工具 → 智能分组」识别箭头/框线标题、正文跨条目标签和 START/END 注释、明确的分区名称前缀，以及已有组内至少两条共用的变量。比如「↓ 一键开关 ↓」到装饰分隔线之间的开关条目会建议归成「一键开关」。同名分区存在时可移入已有分区，不必重复新建；同名候选有多个或依据冲突时不自动决定。无法识别的条目也列在弹窗内，可以手动指定目标。应用前可修改目标、预览完整顺序，支持取消和撤销；移入已有分区时会收拢该组并将新成员放到关闭标记之前（有标记时）。此功能在本地按结构推断，不是对任意正文的 AI 语义分类。
- **新建、复制、编辑条目**：「工具 → ＋ 新建条目」放在选中的条目之后；多选后「更多 → 复制」；点条目右侧的眼睛可改名称、正文、角色和插入位置，点「保存」才生效。
- **分组开关**：只切换分组标记，保留内部每个条目的独立选择，全关的条目也不会被一起打开。生成时是否按分组过滤取决于宿主支持（如柏宝箱）；不支持时仍按条目开关发送。
- **缝后开启**：每条默认与来源一致（来源开着的缝后开启，关着的缝后关闭），「按来源」可一键恢复。总开关向右全开、向左全关，只设置本次待缝入条目；部分开启时滑块居中，仍可逐条调整，确认缝合后生效。
- **状态栏、正文尾这类格式条目**：来源预设靠显示正则把它们变成美化时，目标没有对应正则的话缝过去只显示原文。预览会在这类条目上提醒，确认缝合后可直接打开正则缝合，已预选需要的几条。模型没输出这些标签（掉状态栏）是另一回事，用「思维链 → 正文格式检查」把标签填进必需标签并开启提醒。
- **拖动**：条目右侧的把手拖动单条，分组右侧的把手拖动整组。
- **缝进世界书**：「目标」切换到「世界书」，预设条目、世界书条目都能缝进世界书；预览中可设触发方式、关键词、插入位置、深度和顺序。缝合前自动备份世界书，缝完可在底栏撤销。
- **缝合正则**：在「缝合」页选好来源和目标预设，点来源旁的「正则」。也可从完整预设 JSON 文件读取，不必选择提示词或插入位置。默认只选显示美化；可查看查找式、替换内容及最终顺序，重复自动跳过，同名或同 ID 可保留两份、跳过或指定替换。保留原开关及其他设置。确认后自动按来源预设名归组（可改名，同名组继续使用），分组和正则一起保存、备份、撤销；分组在柏宝箱正则面板中显示，酒馆原生面板仍平铺。目标尚未启用预设正则时，需要到酒馆原生正则面板开启；状态栏还需配套提示词或世界书输出规则能匹配的内容。
- **已选的条目**：缝合底栏点「已选 N 条」查看全部已选条目（跨预设、世界书、粘贴），可逐条去掉。
- **搬到新版**：预设出了新版本时，来源选旧版、目标选新版，在来源旁的「⋯」里点「搬到新版」，旧版中缝进去的条目会按原位置搬到新版，开关状态沿用旧版，原先接入思维链的重新接入。
- **方案**：方案记录预设和条目开关，套用时一并切换。人设默认记当前人设，也可选不记录或其他人设；API 默认不记录（切换方案时 API 不变），可改选当前连接或某个站点，并另选模型。下次保存沿用这次的选择。「条目开关的保存范围」里选「保存全部条目」时，整个预设每条的开关都按方案恢复；选分组时只恢复这些分组，其他条目不受影响。✏️ 里「用现在的状态覆盖」更新条目开关，人设和 API 可勾选是否一起更新；「人设」「API 和模型」可随时修改或改回不记录。
- **推理格式跟随预设**：「更多 → 方案」中开启「切换预设时，同时切换推理格式」后，离开预设时记下酒馆「推理内容格式化」的设置（自动解析、前缀、后缀等），切回该预设时自动恢复。默认关闭。开启后点右侧「已记 N 个」查看各预设记住的设置，可手动修改、删除，或给还没记录的预设新建；改当前预设会立即改酒馆的设置。

## 正文格式检查与变量修复

在「思维链 → 正文格式检查」中，填写预设实际要求的正文标签名（例如 `content` 或 `正文`），还可填写 `状态栏`、`摘要` 等必需标签。`think`、`thinking` 自动识别，也可补充一个自定义思考标签。必需标签按各出现一对检查，不适合允许同名标签重复多次的格式。

- **手动检查**：读取最近一条 AI 回复的当前原文，或检查粘贴的文字，列出掉标签、不成对、重复、正文裹进思考区、正文夹入思考标签、正文标签外的大段文字（爆思维链）等风险，并显示原文片段。代码块和 HTML 注释中的示例不参与标签检查。
- **修正这条回复**：正文标签写错名（如 `<正文>`、`【content】`）、只有开头或结尾、思考标签没闭合把正文裹进去、正文被酒馆解析进思考区时，可预览修正后的原文再写回聊天。只改名、补齐或移动标签，不增删文字；修正后可撤销。正文前写出的分析、重复标签等需人工处理。
- **下一轮提醒**：默认关闭。按预设开启「发现问题时，下一轮提醒 AI」后，仅在该预设使用中、上一条回复仍有问题时加入临时格式提醒；回复恢复正常后不再提醒。切换聊天、切换预设、生成结束或停止时清除临时提醒。开场白、用户/系统消息、后台 quiet 请求、代写用户消息、续写和提示词试算不触发提醒。需要酒馆提供生成前事件与临时提示接口；缺少接口时仍可手动检查。
- **检测范围**：检查聊天原文 `mes`；可见回复没有正文标签时，才在本地查看 reasoning 字段里有没有正文标签，不展示、不发送思考内容。只有点「修正这条回复」才改写聊天，不补造缺失正文。正文外的明显推理标题仅标记为疑似问题；没有明显标记的语义泄露无法可靠识别。格式提醒不能保证模型永不掉标签，续写也不会自动修好已有内容。

变量检查识别 `setvar/getvar/addvar/incvar/decvar/hasvar` 及对应的全局变量宏，也认 `{{getvar 名}}` 空格写法；只用 `hasvar` 判断存在的变量视为开关，不建议补读取。**不能自动修复所有变量问题**：「修复变量问题」仅为符合条件的内容变量补缺失读取，并整理部分有缝合来源的多余双层变量包裹。已有读取但顺序不对、内容被清空覆盖、计数、动态变量名、条件、脚本、深度插入、复杂嵌套、世界书或其他扩展读取、MVU/酒馆助手等变量系统需要人工核对。思维链片段不会通过通用修复直接输出：在「可能未被读取的内容」里点这一条的「加入思维链读取」，选好思维链和行后加入；写入与读取的变量名只差大小写时，可一键改成读取用的名字。「未发现缺少读取」也不等于变量执行结果全部正确。

在「思维链 → 变量顺序与现状」中可进一步检查**先读后写、清空/删除后读取、未读即被赋值覆盖**，并查看变量操作顺序。顺序检查还识别 `hasvar`、`deletevar/flushvar` 及全局版本、存在检查别名和部分空格写法；它按预设列表推演，不保证与最终提示词的重排结果一致。条件、脚本、深度插入、动态名称、复杂嵌套和对象/数组键操作会列为未推演，不会擅自移动条目。

「读取当前变量状态」只显示当前使用中预设对应的聊天/全局变量名、类型、是否为空等摘要。「记录生成前后变量变化」默认关闭，开启后仅在本页内存中保留最近上下文的变化，不是逐次宏调用追踪，不写入聊天或导出变量正文。当前有值也可能是上一轮留下的值，因此顺序风险仍需人工判断。MVU、酒馆助手等外部变量系统尚未接入。

「正文格式检查 → AI 语义审查」可检查没有明显标签的疑似任务规划、自我指令等内部分析。它使用**酒馆当前的聊天补全连接与模型**，不需另存 API 密钥；需要酒馆提供独立聊天补全请求接口。可以手动检查最近回复或粘贴文字，也可按预设开启生成结束后的自动审查（默认关闭）。每次增加一次模型请求、耗时与费用；本功能只提交这一条可见回复，不主动附上完整聊天、预设或变量值，最多 20000 字符，超长时需选段手检。

语义结果只引用原文片段、依据和模型自报置信度；置信度不是准确率，也不是确定错误。模型可能把角色心理或叙事分析误判为内部分析，结果需人工确认，不会自动删除正文或写入下一轮提醒。无效 JSON、原文不存在的引文和过期结果不采纳。审查可以取消，45 秒超时；开始新生成、切换聊天或预设时取消正在进行的审查。审查中的文字不会作为宏执行。

## 加载体检

酒馆打开较慢时，可在「更多 → 加载体检」中查看这一次打开的测量结果：

- **时间点分开记**：页面 DOM 就绪、酒馆启动完成（APP_READY）、启动完成后仍在进行的请求。「聊天可操作」目前无法可靠测量，显示「未测得」，不用启动完成的时间代替。
- **请求按类别统计**：设置及预设、全部角色列表、单张角色详情、聊天记录、扩展清单、扩展脚本与样式、世界书、头像与背景、设置保存，以及已识别的第三方快速接口（柏宝库、鸡尾酒+）。同类请求同时进行时，耗时按时间段的并集算，不相加。
- **体积分三种**：实际传输（经过网络的字节，缓存命中时为 0）、压缩后、解压后。跨域拿不到的标「未取得」。全部预设的大小是内存中序列化后的统计量，不是网络传输量。
- **每笔请求明细**：开始、耗时、等待首字节、接收阶段。等待首字节包含网络往返，不等于服务器处理时间。
- **导出诊断报告**（JSON）：包含版本、统计口径和这次测量覆盖不到的部分；不含预设正文、聊天内容和密钥，角色、头像、聊天等文件名已隐去。

体检只读取浏览器已有的请求记录，不重新下载预设、角色或扩展源码，不判断请求是哪个扩展发起的。检查和导出都只在本浏览器中进行，不上传任何数据。

## 预设清理

酒馆每次打开都会把预设文件夹里的全部预设下载一遍。在「更多 → 清理」中可以看到每个预设的大小，以及自动标出的可清理预设：与另一个完全相同、有新版本、同系列副本、大部分条目与另一个相同。「可清理」把相近的两份折叠成一组，两份都列出并标出建议保留哪份，由你勾选清理哪一份。正在使用的预设不能勾选。

- **归档**：把预设移到酒馆服务器的用户文件目录，打开酒馆时不再下载，在「已归档」中可随时恢复，换设备、换浏览器都能恢复。套用方案时，如果对应预设已归档，会自动恢复。
- **下载**：把勾选的预设打包成 zip 下载到本地。
- **删除**：从服务器上删除，无法在酒馆中恢复，删除前可先下载。

「清理」还有四栏：

- **扩展数据**：设置文件中各扩展的数据量；可「实际检测」哪些数据已没有扩展使用（卸载后的残留），删除前先下载备份。
- **角色卡**：同名角色卡，删除时保留聊天记录。
- **世界书**：内容完全相同的、没有条目的世界书，删除前先下载 zip。
- **本地备份**：本扩展在本浏览器中保存的预设备份。

云端酒馆和安卓本地酒馆（Termux）均可使用。本地酒馆没有带宽瓶颈，归档对打开速度的提升较小。

## 外观

在「更多 → 外观」中选择配色：默认跟随酒馆主题（自动改为不透明，保证文字清楚），也可选用「花田」「晴野」油画渐变，秋樱、海雾、春芽、春和、玫瑰芋泥、日落海岸等画面风格背景，或深色「夜雾」。「文字大小」可选小、标准、大，每台设备单独记；手机上默认比平板、电脑紧凑。还可设置自定义背景图，图片只保存在本浏览器。

## 开发

源码在 `src/`，修改后运行：

```
node build.mjs              # 生成 index.js（扩展版）；dist/ 中的脚本版不提交
node test/run-core.cjs      # 核心逻辑测试
bash test/run-browser.sh    # 全部浏览器检查（首次会在 test/ 下装 playwright 和 jquery）
```

推送和提交合并请求时，GitHub Actions 会自动构建并跑以上测试（`.github/workflows/test.yml`）；`index.js` 与源码不一致时会报错，记得构建后一起提交。

仓库中不包含任何真实预设。测试用的预设都是代码生成的测试数据（`test/fixtures/make-zsx-like.cjs` 和 `test/run-core.cjs` 里的合成预设）。核心测试里有 6 项需要本地的 Ako 预设，没有时自动跳过，同样的场景已有合成预设覆盖。使用真实预设测试时，放入 `test/site/local/`（已加入 .gitignore）。

`index.js` 为生成文件，请勿直接修改。

真实酒馆接口验证步骤和测试范围见 [2.2.0 验证说明](docs/validation-2.2.0.md)。语义 API 的自动化验证使用本地协议桩，不代表已经评估真实模型的判断准确率。
