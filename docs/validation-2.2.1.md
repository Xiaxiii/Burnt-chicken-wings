# 2.2.1 分区归整与保存事件验证

## 行为

整理页按已有分组 id 识别「第 1/4 段」这类被隔开的区段，不依赖 AI。可以从列表提示、「智能分组」或单个分组菜单进入预览，选择需要归整的组。各组成员按原先后集中到该组首次出现的位置，其余条目的相对先后不变。应用后沿用自动保存、备份和一次撤销。

这会调整真实预设条目顺序，可能改变变量等规则的执行先后，应用前可以查看完整顺序。未分组条目不按名称或正文猜测归属，同名但 id 不同的分组也不合并。

普通保存此前为了清除柏宝箱旧分组缓存，会广播 `OAI_PRESET_IMPORT_READY`，从而同时调用其他扩展的导入监听器。本次仅使柏宝箱当前预设的分组缓存失效，保留正常的预设更新事件，不再制造导入事件。没有拦截提示框，也没有移除其他扩展的监听器；真正导入仍按酒馆原有流程运行。

## 检查

```bash
node build.mjs
node --check index.js
node test/run-core.cjs
PW_CHROME=/usr/bin/chromium bash test/run-browser.sh
git diff --check
```

核心/运行时检查 125 项通过，6 项依赖本地私有 Ako 预设的可选检查跳过。新增 10 项分区检查和 4 项宿主保存检查，覆盖：

- 四段分区与交错分组、单组勾选、同名不同 id、空分组、未分组和系统占位符。
- 预览不修改草稿，移动保留开关、正文、第三方字段和其他角色的顺序，重复应用不产生移动。
- 柏宝箱及 `entryGrouping` 成员列表两种格式保存重读，组外条目不被吞入，完整撤销。
- 当前预设的缓存失效、其他预设缓存保留、未安装柏宝箱，以及真实导入监听不受影响。

`test/group-repair-check.mjs` 在手机和桌面视口验证提示、入口、完整预览、取消、部分/批量移动、自动保存、撤销，以及预览期间修改草稿后拒绝应用过期结果。`test/group-check.mjs` 验证缓存不再覆盖新建分组，并确认普通保存不会调用导入监听器。

全部 22 个浏览器检查脚本通过，执行清单与 `test/*-check.mjs` 完全一致，运行器退出码为 0。

旧版宿主保存代码已用相同回归断言复现：普通保存会发送导入事件，因而断言失败；修复后通过。

## 验证范围

柏宝箱缓存字段依据其 1.1.0 源码、提交 `58eace59f29fdd76f5d265c545cd632569be9508` 核对：全局运行时对象的 `presetPromptGroupRuntimePresetName` 与 `presetPromptGroupRuntimeState` 是其清缓存逻辑删除的两个字段。本次测试模拟这组接口与旧缓存回写行为，没有声称已验证完整柏宝箱与用户实际安装脚本的组合。

提示「[导入自动] 未找到可迁移的缝合源预设」的具体输出脚本尚未取得。本次修复鸡翅普通保存误触发导入监听器的路径；如果其他脚本在启动或真实导入时自行发出同样提示，需要继续核对该脚本的触发条件。

没有测试用户截图中的真实预设，测试材料均为合成数据。2.2.0 已列出的变量修复待办仍未改变，见 [2.2.0 验证说明](validation-2.2.0.md)。
