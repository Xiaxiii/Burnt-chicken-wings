# 2.2.2 未分组条目识别验证

## 修复的遗漏

2.2.1 新增的是「已有分组的分散成员归整」，没有补齐未分组条目的识别。旧识别器不认识截图中的「↓ 一键开关 ↓」，只能返回空建议。把上一版描述为已经解决这类未分组情况并不准确。

本次在 `test/fixtures/ungrouped-sections.cjs` 用截图可见名称与边界构造合成输入，正文为测试文本。旧版执行结果已复现为 `[]`。修复后建议包括「一键开关」的标题和 7 条开关；装饰线、后面的思维链区和系统占位符不被吞入。

## 现在的规则与流程

- 支持向下/向上箭头、常见框线标题、装饰分隔线，以及正文中跨条目的标签与 START/END 注释。箭头标题的正文长度不再限制识别。
- 分区名称唯一匹配现有分组时默认建议移入；无现有同名分组时建议新建。存在多个同名候选时由用户选择。
- 未分组条目的明确名称前缀，或已有分区内至少两个成员共用且没有跨组使用的变量，可以形成归属建议。名称和变量指向不同分组时不自动采用。
- 「基础需求-一键开关」等控制条目优先留在已识别的开关区；脱离开关区时也不因名称含被控分区名而自动塞入该分区。
- 未识别归属的条目仍列在弹窗内，可以指定目标。无任何规则命中时仍有可操作列表，默认不勾选。
- 新建与移入在副本上计算，完整预览显示最终归属与顺序。应用同一份预览结果，整批可撤销；预览期间预设发生变化时拒绝应用。
- 移入已有分组会收拢该组分散成员，并尽量放在组末关闭标记之前；保留正文、条目开关及原有分组设置，生效时遵循目标分组的开关。

这是本地结构推断，不调用模型，不执行条目里的宏，不提供任意正文的语义分类保证。本次没有取得用户原始预设，也没有要求提供它作为继续修复的前提。
